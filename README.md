# Food Log

Локальный Telegram-бот для пищевого дневника в закрытой группе с тренером.
Принимает фото с подписями и описания еды через `/food`, оценивает калории и БЖУ через OpenAI API, сохраняет
дневник в SQLite. `/today` присылает альбом: итог дня, калории по приёмам пищи и БЖУ.
`/week` присылает альбом из двух диаграмм за последние 7 дней,
включая сегодня, с общей подписью периода: «Отчёт за 09.11.2026–15.11.2026».

## Первый запуск на macOS

Для установки с нуля нужен Python
3.11 или новее; проверено на Python 3.14.7.

```sh
git clone https://github.com/zhupanovdm/food-blogger-bot.git
cd food-blogger-bot
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock.txt
```

1. Создай бота через [@BotFather](https://t.me/BotFather), команда `/newbot`.
   Добавь в закрытую группу себя, тренера и бота.
2. В BotFather выполни `/setprivacy`, выбери этого бота и **Disable**.
   Если бот уже в группе, удали и добавь его заново, чтобы настройка применилась.
   Права администратора не нужны. Бот увидит сообщения группы, но программа
   анализирует только еду владельца и связанные с ней уточнения.
3. Открой локальный `.env` в редакторе. Если файла нет: `cp .env.example .env`.
   Вставь `TELEGRAM_BOT_TOKEN`, поставь `SETUP_MODE=true`.
4. Запусти:

   ```sh
   .venv/bin/python -m food_log
   ```

5. Отправь `/whoami` в группе со своего аккаунта.
   Перенеси в `.env` ID группы в `TELEGRAM_CHAT_ID`, свой ID в
   `TELEGRAM_OWNER_ID`. ID других участников не нужны.
6. Останови программу сочетанием **Ctrl+C**. Укажи `SETUP_MODE=false` и заполни
   `OPENAI_API_KEY` ключом из [OpenAI Platform](https://platform.openai.com/api-keys).
   У аккаунта должен быть доступ к выбранной модели и доступная квота API.
7. Повтори команду запуска. В группе задай цель, например `/goal 2200`, отправь
   фото с подписью и проверь `/today`, `/week`.

Модель по умолчанию — `gpt-4.1-mini`, можно сменить через `OPENAI_MODEL` на доступную
модель OpenAI с изображениями, Responses API и Structured Outputs. Подключение
без ключей не проверено. Никакие реальные сообщения при разработке не отправлялись.

Режим `SETUP_MODE=true` нужен только для начальной настройки: он отвечает на
`/whoami`, не ведёт дневник и может подтвердить Telegram старые события. После
начала учёта для просмотра ID используй `/whoami` в обычном режиме.

## Как пользоваться

В группе введи `/`, чтобы выбрать команду из меню: today, week, goal, help.
Меню регистрируется при запуске и доступно всем участникам настроенной группы.
`/whoami` остаётся служебной командой вне меню. `/goal` показывает цель и подсказку
`Чтобы изменить: /goal 2200`.

- Без фото: `/food обед, рис 150 г, курица 120 г` — отдельный приём пищи.
  Можно не указывать вес: модель оценит типичную порцию и назовёт допущение.
  Команда создаёт новую запись даже при отправке ответом на другую еду.
- Фото: `обед, рис 150 г, курица 120 г, соус отдельно, съел всё`.
- Доля: `вся порция 300 г, съел половину` — бот учитывает 150 г.
- Исправление: ответь **на фото, исходную команду `/food` или сообщение оценки**: `на самом деле съел треть`.
  Повторная оценка заменяет предыдущую.
- Можно отредактировать подпись к исходному фото, сообщение `/food` или текст уточнения. Бот пересчитает
  ту же запись, без новой порции. Самая поздняя редактура имеет приоритет.
- Уточнение обычным сообщением без reply (например, `это ужин`, `порция 200 г`,
  `съел половину`, `без сахара`) относится к последней добавленной записи за 24 часа (даже после переноса еды на вчера).
  Обычные разговоры не должны запускать пересчёт. Для произвольной формулировки
  или более ранней записи ответь на фото/оценку либо начни с `уточнение:`.
- Без точного веса модель сначала оценивает массу порций по фото, затем калории
  и БЖУ. Вопросов о весе нет: допущения кратко перечислены, их можно поправить.
- Несколько ракурсов одной тарелки не считаются дополнительными порциями.
- Дату, время и тип еды можно указать в подписи, `/food` или ответе на запись:
  `вчера ужин в 20:30`, `сегодня завтрак`, `19.11.2026 в 08:00`,
  `19 ноября в 8 вечера`. Поддерживаются также `позавчера`, `вчерашний ужин`,
  `YYYY-MM-DD`, короткая дата `дата 19.11` / `19.11 ужин` (год сообщения) и `в 8 часов`.
  В произвольном описании еды указывай дату с годом или словом «дата», чтобы
  не спутать её с дробным количеством вроде «1.50 стакана».
- Дата, время и тип исправляются независимо. Например, ответ `в 21:15`
  меняет только время, `вчера` — только дату, `это ужин` — только тип.
  Последнее явное значение в истории имеет приоритет; остальные сведения сохраняются.
- «Вчера» отсчитывается от дня отправки того сообщения, где оно написано,
  в `TIMEZONE`, а не от дня обработки или редактирования. Повтор не сдвигает дату.
- Если время еды не задано, сохраняется время исходного сообщения; в ответе это
  явно отмечено. Название «поздний ужин» само по себе не задаёт точный час.
  Без явного типа он определяется по исправленному местному времени:
  06–11 завтрак, 11–16 обед, 16–18 полдник, 18–23 ужин, ночью перекус.
- Исправление только даты/времени/типа готовой оценки не меняет калории и БЖУ
  и не вызывает модель. Если меняется состав или порция, еда пересчитывается.
  Неверные даты и время дают подсказку; прежние дата и оценка сохраняются.
- Альбом анализируется как один приём пищи после 8 секунд без новых фото альбома.
- Любой участник группы может вызвать `/today`, `/week`, `/goal` и `/help`.
  Добавление еды, исправления и изменение цели принимаются только от владельца дневника.

| Команда | Результат |
|---|---|
| `/food описание` | Добавить отдельный приём пищи без фото, доступно только тебе |
| `/today` | Альбом: итог дня, калории по приёмам и БЖУ |
| `/week` | Один альбом из двух PNG с периодом: калории и БЖУ |
| `/goal 2200` | Задать текущую цель в ккал/день, доступно только тебе |
| `/goal` | Посмотреть цель |
| `/whoami` | ID группы и автора сообщения |
| `/help` | Краткая справка |

Цель — введённое пользователем число, не рекомендация бота. На всём графике
отображается текущая цель. Дни определяются в `TIMEZONE`, по умолчанию Europe/Moscow.
Выходные подписаны красным. Пропуски не считаются нулями; сегодняшние значения
могут увеличиваться. Бот не определяет автоматически, записал ли ты всю еду за день.

В дневном итоге круг показывает потребление и остаток до цели. При превышении
красный сектор показывает лишние калории, а процент справа считается от цели:
2700 при цели 2200 — 122,7%. «Сегодня» зелёный до цели включительно, красный выше.
Среднее — за предыдущие 7 календарных дней, без сегодняшнего, только по дням
с записями; рядом указан период и покрытие. Приёмы идут по уточнённым дате и времени еды,
повторяющиеся категории не объединяются. Доля каждого приёма считается от цели.

## Хранение и сбои

- `.env` и `data/` исключены из Git. Не публикуй их: в базе личный дневник.
- Фото, описания еды и история уточнений отправляются в OpenAI. В запросе `store=false`;
  это не обещание отсутствия служебного хранения у провайдера.
- На диске сохраняются Telegram file_id, подписи, уточнения и результаты анализа.
  Исходные фото скачиваются в память для анализа.
- После получения события работа сохраняется в SQLite; перезапуск продолжит очередь.
- При ошибке анализа — до 3 попыток, затем сообщение в группе. Для повтора ответь
  `повтори` на исходное сообщение еды или ответ бота. Предыдущий результат при сбое сохраняется.
- В новых оценках нет гликемического индекса и нагрузки. Старые записи читаются
  без потери калорий и БЖУ; при пересчёте устаревшие поля больше не сохраняются.
- При исправлении даты/времени итоги переходят в нужный день без дублирования еды.
- Для старых отредактированных уточнений исходное время отправки раньше не
  сохранялось: при чтении такой записи используется сохранённое время её редакции.
  При сомнениях укажи абсолютную дату, например `19.11.2026 в 20:30`.
- Редактура фото и сохранённых уточнений обрабатывается через `edited_message`.
  Редактура `/food` пересчитывает существующую запись; остальные отредактированные
  команды повторно не выполняются.
- При аварии между отправкой ответа и подтверждением в базе возможен повтор
  ответа или PNG; записи еды от этого не удваиваются.
- Telegram не сообщает конец альбома: очень позднее фото может вызвать пересчёт
  и дополнительный запрос модели. Для разной еды лучше отдельные сообщения.
- Компьютер должен работать и иметь интернет. Telegram хранит неполученные
  события [не дольше 24 часов](https://core.telegram.org/bots/api#getting-updates).
- Не запускай второй экземпляр с тем же ботом. Настроенный webhook нужно отключить
  вручную или выбрать другого бота; сервис сам его не удаляет.

Для резервной копии останови бота и скопируй папку `data/`. Не меняй бота, группу
или владельца для уже заполненной базы: для другого дневника используй новую папку.

## Проверка и устройство

```sh
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m compileall -q food_log
.venv/bin/python -m pip check
```

- `food_log/__main__.py` — настройки, режим получения ID и запуск.
- `food_log/service.py` — Telegram, OpenAI и обработка событий.
- `food_log/store.py` — SQLite, очередь, исправления, суммы.
- `food_log/nutrition.py` — валидация ответа модели и расчёт долей.
- `food_log/charts.py` — три дневных и две недельных диаграммы.
- [Состояние проекта](docs/project-state.md), [описание](docs/superpowers/specs/2026-11-15-food-log-design.md).

Проверки API используют подменённые ответы. Для живой проверки нужны ключи,
отправка фото и `/food`, исправление порции, оба отчёта и перезапуск с сохранением записей.
