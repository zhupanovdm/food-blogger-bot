# Food Log: первая локальная версия

Дата: 2026-11-15. Обновлено 2026-11-20; изменения даты/времени пока в Unreleased.
Базовая архитектура с OpenAI API согласована.
Графические отчёты согласованы с последними уточнениями и реализованы локально.

## Результат

Telegram-бот работает с компьютера пользователя и ведёт дневник в одной закрытой
группе с тренером. Интерфейс — сообщения и команды Telegram; отдельного сайта нет.

## Использование

1. Пользователь отправляет фото еды с необязательной подписью о составе и порции
   либо `/food описание` без фото. Команда создаёт отдельную запись; её редактура
   и ответы на неё исправляют эту же запись. Без веса используется типичная порция.
   Подпись передаётся модели вместе с фото. Указанные пользователем вес, съеденная
   доля, ингредиенты и способ приготовления имеют приоритет над предположениями
   по изображению. Показатели рассчитываются для съеденного количества:
   «порция 300 г, съел половину» означает учёт 150 г. Если указан вес уже съеденной
   еды, повторно уменьшать его нельзя. По последнему решению пользователя модель
   сначала сама оценивает массу порций, затем калории и БЖУ, не требует точного
   веса. При неоднозначности использует наиболее вероятные допущения и явно их
   указывает; пользователь может исправить готовую оценку. Догадки не выдаются за факты.
2. Бот оценивает состав, вес, калории, белки, жиры и углеводы, сохраняет запись
   и отвечает с пометкой «приблизительная оценка» и существенными допущениями.
3. Пользователь отвечает на сообщение бота уточнением. Бот пересчитывает
   существующую запись, сохраняя связь с исходным фото; новая порция не добавляется.
   Поддерживаются также редактура подписи/уточнения и обычный текст в чат:
   без reply он относится к последнему приёму пищи за предшествующие 24 часа.
   Явный reply к неизвестному сообщению не переносится на другую запись.
   Явные дата/время из текста имеют приоритет над временем сообщения.
   Дата, время и категория корректируются независимо, без новой записи;
   подробности в [описании изменений](2026-11-20-meal-datetime-design.md).
   Приём пищи по уточнённому времени: 06–11 завтрак, 11–16 обед,
   16–18 полдник, 18–23 ужин, иначе перекус. Последнее явное указание категории
   в подписи/редактуре/уточнении важнее времени и предыдущего текста.
4. `/today` показывает итог текущего дня, `/week` — последние семь календарных
   дней, включая текущий, по отдельности. Время — Europe/Moscow.
5. Дни без записей обозначаются как «нет записей». Среднее за дни с записями
   называется именно так: полноту дневника бот не может определить сам.

## Границы и безопасность

- Учёт фото только указанного пользователя и только в указанной группе.
- Исправления и все команды доступны только владельцу дневника.
- Все сообщения других участников, включая тренера, игнорируются в обычном режиме.
- Сообщения прочих участников и сообщения из других чатов не обрабатываются моделью.
- Несколько фото в альбоме считаются одним приёмом пищи и анализируются совместно.
- Повторная доставка Telegram-события не добавляет повторную запись.
- Если фото не позволяет определить еду, запись с выдуманными значениями не создаётся.
- Фотографии и связанные подписи отправляются внешнему API для анализа.
- Автоматическая рассылка и Mini App вне первой версии. Гликемический индекс и нагрузка исключены из версии v1.1.0.
- Ручной учёт пищи без фотографии доступен через `/food`. Редактирование фото и
  сохранённых уточнений отслеживается; редактура `/food` пересчитывает запись, остальные отредактированные команды не выполняются.
- Несколько ракурсов одного блюда не считаются дополнительными порциями.

## Устройство

Python-сервис использует Telegram Bot API через long polling и OpenAI Responses API
с поддержкой изображений; имя модели задаётся настройкой, по умолчанию gpt-4.1-mini.
Отдельного обучения нет. Калории и БЖУ — оценки модели.
Гликемический индекс, нагрузка и их справочник удалены в v1.1.0.
Старые JSON-оценки читаются с пропуском устаревших полей gi_key и available_carbs;
новые оценки их не содержат. Подробности изменений: [текстовый ввод](2026-11-17-text-meals-design.md).

Модель возвращает структурированные данные. Программа проверяет их типы и
допустимость, хранит записи в SQLite и считает отчёты обычным кодом. Дата и время еды
берутся из явного текста или исходного Telegram-сообщения, а не времени анализа.
Настройки и ключи хранятся в `.env`, база — в `data/`, оба пути исключены из Git.
Сами изображения в базе не сохраняются; сохраняются Telegram file_id и результаты.

Компьютер должен быть включён, подключён к интернету, программа должна работать.
Полученные, но ещё не обработанные задания сохраняются для повторной попытки
после перезапуска. Ошибка API не создаёт нулевой приём пищи и не меняет предыдущую
версию исправляемой записи. Секреты и содержимое фотографий не пишутся в журналы.

## Проверка

Автоматически проверить: суммы калорий и БЖУ, московскую полночь, недельный диапазон,
отсутствие повторного учёта, замену записи при исправлении, ограничения группы и
пользователей, обработку альбома и ошибки модели. Проверить передачу подписей,
расчёт съеденной доли без двойного уменьшения, автоматическую оценку веса без
вопросов, редактуру и приоритет нового текста, категорию по местному времени.
Внешние API в тестах подменяются.

Живая проверка после настройки ключей: отправить фото, уточнить порцию ответом,
проверить оба отчёта и сохранность дневника после перезапуска. Без ключей нельзя
считать взаимодействие с Telegram и моделью проверенным.

## Источники ограничений

- Telegram хранит неполученные события не дольше 24 часов:
  https://core.telegram.org/bots/api#getting-updates
- Видимость сообщений в группе зависит от privacy mode:
  https://core.telegram.org/bots/features#privacy-mode

## Исторические требования к графикам v1.0.0

С 17.11.2026 недельный альбом содержит только калории и БЖУ; требования ниже
к гликемической нагрузке и трём недельным графикам отменены в v1.1.0.

Пользователь согласовал эскизы и разрешил реализацию после следующих уточнений.

- `/week`: последние 7 календарных дней, включая текущий. Показать PNG с линией
  ежедневных калорий и пунктиром текущей цели. Дни без записей — разрывы линии,
  текущий незавершённый день отмечен отдельно. Полнота прошлых дней не гарантирована.
- Три диаграммы отправляются одним альбомом через sendMediaGroup. Общая подпись
  у первой картинки содержит период с годом: «Отчёт за DD.MM.YYYY–DD.MM.YYYY».
  Короткие статусы ожидающих/ошибочных записей при наличии добавляются туда же.
- Цель калорий задаётся командой бота; предложенный синтаксис `/goal 2200`.
- Для гликемических показателей предложены столбцы расчётной гликемической нагрузки
  по дням с разбивкой по приёмам пищи. Источником ГИ должен быть справочник;
  неизвестные значения не заменяются нулями. Неполные данные отмечаются явно.
- Эскизы: `docs/mockups/calories-preview.png` (эскиз гликемической нагрузки удалён в v1.1.0).
  Все значения в эскизах вымышлены. Реальный рендерер — `food_log/charts.py`.
- Уточнения к оформлению: выходные даты и дни недели красным; легенды отдельными
  компактными блоками внутри графиков; длинных пояснений под графиками нет.
- Дополнительный эскиз БЖУ: `docs/mockups/macros-preview.png`. На каждый день
  три столбца рядом: белки, жиры, углеводы в граммах. Цвета фиксированы,
  текущий незавершённый день выделен штриховкой, пропущенные дни не равны нулю.
- Единицы измерения рядом со шкалой оси Y. Из легенд убраны «Разрыв — нет записей»
  и слово «пока»; подпись текущего дня — «Сегодня».
- «≈ оценка» также находится в подписи оси Y; отдельного пояснения снизу нет.
- Шкалы адаптируются к данным и цели. В гликемическом графике «нет записей»
  отличается от «нет оценки»; частичные итоги штрихованы и помечены `+ ?`.
- Обработка альбома начинается после 8 секунд без новых фото этого альбома.
  Telegram не присылает признак конца альбома, поэтому очень поздние снимки
  могут привести к пересчёту. При аварии после отправки ответа, но до фиксации
  доставки возможен повтор ответа; сама запись еды не удваивается.
