# Дата, время и категория еды

Поручение 20.11.2026: учитывать эти сведения в исходном описании и исправлениях.
Диагностика UI Telegram и локальной БД подтвердила: «Вчера ужин…» и «Ужин вчера»
меняли только category; eaten_at оставалось датой отправки. «8:00 омлет…» также
не меняло eaten_at. PATTERN не распознавал категорию после слова «вчера».

- Детерминированно разбирать сегодня/вчера/позавчера, вчерашний, даты DD.MM[.YYYY],
  YYYY-MM-DD, D месяца [YYYY], время HH:MM, «в H часов», «в H утра/вечера».
- Короткие DD.MM распознаются только с маркером «дата» либо отдельным
  указанием даты рядом со временем/категорией. Дробные количества еды не даты.
  Категория распознаётся также после слов утром/днём/вечером/ночью.
- Относительная дата привязана к исходному времени соответствующего сообщения
  в TIMEZONE, а не к моменту анализа, редактуре или уже перенесённой дате еды.
- Дата, время и категория исправляются независимо, последнее явное значение
  в хронологии актуальных сообщений имеет приоритет. Без явной категории
  категория определяется по исправленному времени. Без времени сохраняется
  время исходного сообщения с явным пояснением в ответе.
- Хранить original_at приёма и sent_at исходных фото/заметок для устойчивого
  повторного вычисления. Для старых фото original_at — время первого фото,
  для старых заметок доступно только updated_at; не подменять это фактом.
- Перенос eaten_at и сохранение оценки выполняются атомарно. Новая запись не
  создаётся. Исправление только даты/времени/категории сохраняет калории и БЖУ,
  не вызывает OpenAI при наличии готовой оценки без незавершённых изменений.
- Последняя запись для свободного уточнения выбирается по original_at за сутки,
  чтобы перенос на вчера не разрывал возможность её уточнить.
- Ответ содержит дату, время и категорию; неверная дата/время дают явную ошибку,
  без выдуманной даты и без повреждения прежней оценки.

  Перед обновлением — резервная SQLite-копия. Сохранённые даты/категории
  восстановить из истории без OpenAI и без отправки сообщений в Telegram.
